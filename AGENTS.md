# AuCourant

Android app that sorts MoMo payment SMS: by reference for churches and organisations, by money in and out and category for personal or business use. Product intent: `docs/aucourant.prd.md`. Engineering decisions: `docs/architecture.md` and `docs/architecture-personal.md`. Figma is no longer used: `docs/figma-brief.md` and `docs/figma-prompt.md` are historical and not maintained.

**Stack:** Expo SDK 58 (React Native 0.88, TypeScript) for the UI. Java for everything native. Android only.

## Layout

```
App.tsx                      fonts, providers
src/AppShell.tsx             screen switcher, bottom nav, Android back button
src/lib/                     store (state + actions), sample data, formatting, report builders
                             personal*.ts, categorise.ts, periods.ts: the Personal use type
src/screens/                 one file per area (onboarding, home, groups, transactions, review, export, settings, lock, codes)
src/screens/personal/        Personal views: home, transactions, person, categories, export
src/ui/                      kit (buttons, rows, fields), overlays (sheet, dialog, snackbar, coach marks), icons
src/theme/                   colour and type tokens (Midnight Emerald Gold, dark + light), makeStyles
src/native/                  typed bridge to the Java modules
native/android/java/...      Java sources: ExportModule, LockModule, SmsModule (nativebridge/), MTN parser registry (parser/)
native/android/test/...      plain-JDK parser checks (no Android, no JUnit)
plugins/with-aucourant-native.js   copies the Java into android/ and registers it on every prebuild
```

Navigation is a small state machine in `src/lib/store.tsx` (phase: onboarding, locked, app; plus a route stack). It mirrors the Figma Make prototype. Expo Router is not used.

## Rules

- `android/` is generated by `npx expo prebuild` and is gitignored. Never edit it by hand. Java goes in `native/android/java`; manifest or Gradle changes go in `app.json` or the config plugin.
- Add packages with `npx expo install <pkg>` so versions match the SDK.
- Import icons from `src/ui/icons.ts` (deep imports keep the bundle small). Add new ones there.
- Fonts are imported per weight (`@expo-google-fonts/inter/500Medium`), never from the package root.
- Use `T` for text and `makeStyles` for themed styles. Colours come from tokens, never hard-coded, except brand moments (`BRAND`).
- Copy follows the PRD wording: *service* for Church, *period* or *meeting* for Organisation, *period*, *category*, *money in* and *money out* for Personal or business.
- The raw SMS in `src/lib/personal-data.ts` and the Java templates use the same wording. Change both together and run `npm run test:parser`.
- The `parser/` package must stay free of Android imports so it can be tested with only the JDK.

## Commands

```bash
npx expo run:android        # build and install the dev app (emulator or USB phone), then starts Metro
npx expo start              # Metro only, for an already installed dev build
npx tsc --noEmit            # typecheck
npm run test:parser         # Java parser checks with only the JDK (uses JAVA_HOME or Android Studio's JBR)
npx expo-doctor             # config and dependency checks
npx expo prebuild --clean   # regenerate android/ after changing app.json or the plugin
```

Gradle needs JDK 17 or 21. On this machine use Android Studio's: `JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"`.

Expo Go cannot run this app: it has its own Java modules. Use a development build (`npx expo run:android`).

## State of the app

The UI runs on the prototype's sample data. Real today: the Android SMS permission prompt, report files written and shared by `ExportModule`, PBKDF2 hashing and recovery codes in `LockModule` (not yet wired to the lock screens), and the MTN parser registry with reference cleaner (`SmsModule.parseMessages`; sent, merchant, bill, cash out, airtime and reversal templates are provisional). Still to build: live SMS receiver, Room storage connecting parser output to the screens, biometric unlock.

The use type (Church, Organisation, Personal or business) switches the tabs and screens. Personal has its own sample data and state slice.

In development builds, Settings has a Developer section with the prototype's flows (F1 to F6, church), screen states (loading, empty, error), a motion toggle, and *Parse my inbox* (runs the Java parser over the phone's real MoMo messages, stores nothing).
